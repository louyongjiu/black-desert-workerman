# Black Desert Workerman

黑色沙漠工人与节点规划工具，用于管理工人任务、估算采集点和工作坊收益，并查看节点连接与贡献点成本。

项目使用 Vue 3、Pinia、Vite、deck.gl、ECharts 和 WebAssembly。地图底图、图标、游戏静态数据及 WASM 均随仓库提供，市场价格通过外部接口获取。

## 功能

- 管理工人属性、技能及任务分配。
- 根据工人属性、产出、距离、资源设置和价格估算收益，比较采集点与工人方案。
- 查看地图节点、连接路径、地区和资源分组，计算贡献点成本。
- 配置工作坊、住宿和仓库，并查看相关成本与收益。
- 查看掉落率和鱼类尺寸统计。
- 在浏览器中保存设置，支持通过页面导入、导出配置。
- 在 **帝国优化** 中按贡献点预算联合规划采集点、工人城镇、连接节点、住宿和指定仓库，支持限时求解、停止保留方案、导出、应用及撤销。
- 在 **住房规划** 中融合 bdo-housecraft 的房屋依赖模型，可保留住宅、仓库、住宿或工坊用途，按实际占用求解并保存方案；共享前置房屋只计算一次贡献点。

## 界面操作

- 首页可直接搜索节点、物品或城镇，支持方向键和回车选择；首次使用会显示设置、导入及规划入口。窄屏下可切换地图、工人列表和节点详情。
- 价格管理支持物品搜索，以及自定义价格、自用物品和缺价筛选。无效价格输入会显示提示并保留原数值。
- 配置导入会先校验 JSON，再显示将覆盖的设置和数量，确认后才生效。解雇、清空及导入支持本次页面会话中最近一次操作的撤销；再次编辑相关数据后会禁用撤销。
- 弹窗支持关闭按钮、Escape 和键盘焦点循环。采集点表格默认突出收益，详细列可展开，窄屏滚动限制在表格内部。
- 帝国优化默认显示预算和产物仓库，其余参数可展开。结果提供当前方案与新方案的指标对比、节点增减及应用条件说明。
- 住房草稿保存在当前浏览器，刷新后可继续编辑；保存按钮显示全部待保存城镇数量。试算草稿的计算结果需要重新计算，已保存的试算记录保持可用。

## 本地运行

推荐使用 Node.js 22 和 npm，这是当前验证所用的环境。

```sh
git clone https://github.com/louyongjiu/black-desert-workerman.git
cd black-desert-workerman
npm ci
npm run dev
```

打开终端显示的 `/workerman/` 地址，通常为 `http://localhost:5173/workerman/`。开发模式支持源码修改后的自动更新；端口被占用时，以终端输出为准。

首次使用时，先在 **Settings** 中选择服务器、语言和税率，再查看工人及采集点收益。

帝国优化入口为 `/workerman/optimizer`。先更新价格，再选择预算、城镇、产物仓库和采集点候选数量。新采集工人使用 40 级平均属性及建议技能；应用只替换采集工人，保留现有工坊工人、闲置工人和自定义房屋用途。工坊必需连接、全部保留工人的床位、材料/成品仓储与新采集共同规划，共用节点和房屋只计一次贡献点。应用及导出使用同一份合并方案，支持撤销。活动围栏、自定义、贸易或皇室工坊任务尚未进入混合模型时，只允许导出预览说明，不自动删除或关闭原设置。

住房入口位于 **帝国优化**，分别进入“帝国住房设置”和“自由试算”。原 `/workerman/housecraft` 默认进入帝国住房，`/workerman/housecraft?mode=trial` 可直接进入自由试算。帝国模式的自定义用途和工坊仓储先编辑草稿，点击“保存设置并返回帝国优化”后生效，再计算、应用完整方案。自由试算有独立的总工人数、总仓储需求、免费及付费容量和保留用途；点击“开始试算”计算，保存仅记录本机比较数据。两个模式分别支持重置和撤销，切换城镇与页面保留当前草稿；帝国重置只清除本城镇草稿的手动用途，不删除试算记录。详细说明见 [住房规划](src/housing/README.md)。

优化页面默认选择全部有有效价格的采集点和全部可用工人城镇，也可缩小范围。优化器在浏览器 Worker 中运行，无需 Python 或后端服务。候选范围和时间上限会影响结果；页面显示当前可行方案及求解差距。实现与验证说明见 [浏览器优化器](src/optimizer/README.md)。

## 构建与预览

```sh
npm run build
npm run preview
```

构建输出到 `dist/`。预览地址通常为 `http://localhost:4173/workerman/`，具体地址以终端输出为准。

如需指定端口：

```sh
npm run preview -- --host 127.0.0.1 --port 5191
```

构建脚本会生成语言片段、编译前端、清理过期资源，并将运行所需的资源发布到 `dist/data/<内容哈希>/`。JSON 在发布时去除空白，游戏数据合并为基础包和规划包；地图瓦片、图标及说明图片使用稳定的目录内容哈希。历史观测文件和完整语言源文件保留在源码仓库。

地图瓦片在生产构建时由 Sharp 生成压缩候选：最大尺寸 192×192、WebP 质量 60、编码 effort 6。每张图片仅在候选文件严格更小时采用压缩版，否则发布原始字节。`data/maptiles/` 中的原始图片保持原样，文件名、地理范围和 `tileSize` 保持原值，节点图标与连接线仍由独立图层绘制。开发服务使用原图；通过 `npm run build` 和 `npm run preview` 查看生产压缩效果。

首次构建会处理全部瓦片并输出进度和体积统计；后续构建复用 `.cache/maptiles/` 中按原图内容、压缩参数和编码器版本生成的缓存。缓存不纳入版本控制。Sharp 为构建依赖，要求 Node.js 20.9 及以上，推荐继续使用 Node.js 22。

发布时使用完整的 `dist/` 目录。当前访问前缀在 `vite.config.js` 中设为 `/workerman/`；页面路由使用 History 模式，托管服务需将应用路径下未匹配的页面请求回退到入口 `index.html`，同时保留静态资源的正常访问。

仓库包含 `vercel.json`，指定构建命令、输出目录、`/workerman/` 的静态资源映射和页面回退。带内容哈希的资源使用一年浏览器缓存；资源内容变化后 URL 自动更新。Vercel 按浏览器支持自动提供 Gzip 或 Brotli 压缩。

市场主接口通过同域 `/api/bdolytics/market` 请求，由 Vercel rewrite 转发到 BDOlytics，避免浏览器跨域限制；语言与服务器参数随查询字符串转发。本地开发及预览使用 Vite 代理。修改后需要重新部署，且部署需包含仓库根目录的 `vercel.json`，只上传 `dist/` 不会带上代理配置。其他托管平台也需配置同一路径的反向代理。

Settings 中的 **Map data saver (lower image detail)** 可限制地图最高瓦片层级，减少放大地图时的下载量。默认加载全部层级；生产底图采用上述均衡压缩。

如果已有独立静态资源 CDN，可设置构建环境变量 `VITE_ASSET_BASE_URL`，例如 `https://assets.example.com/workerman/`，并将完整的 `dist/data/` 同步到该地址下的 `data/` 目录。CDN 需要允许网页域名的 CORS 请求，并保留 JSON、GeoJSON 和图片的正确 Content-Type。JavaScript、CSS 和 WASM 继续通过 Vercel 加载。

分包范围、缓存更新方式和本地测量见 [静态资源优化说明](docs/static-resources.md)。

## 目录说明

| 目录或文件 | 内容 |
|---|---|
| `src/` | Vue 页面、组件、状态管理及计算逻辑 |
| `src/pkg/` | WASM 路由模块与 JavaScript 接口 |
| `data/` | 游戏静态数据、观测数据与图片资源 |
| `data/maptiles/` | 本地地图瓦片，文件格式为 `{z}/{x}_{y}.webp` |
| `data/icons/` | 物品、节点、技能及其他图标 |
| `data/images/` | 页面说明图片与示意图 |
| `data/loc.json` | 完整语言数据，修改语言文本时编辑此文件 |
| `data/loc/` | 开发和构建时生成的单语言 JSON 文件 |
| `data/ui/` | 按语言和页面生成的界面词典，来源为 `src/i18n/` |
| `public/` | favicon 等公共资源 |
| `scripts/` | 构建及语言文件生成脚本 |
| `tests/` | 计算逻辑和性能相关回归测试 |
| `docs/performance.md` | 性能改动、测量条件与验证记录 |
| `dist/` | 构建结果，不纳入版本控制 |

地图瓦片、图标、语言文件及 WASM 已纳入版本控制。正常克隆仓库后，无需从其他本机目录复制图片。

## 数据与联网

图片、地图瓦片、前端脚本、样式、游戏静态数据和 WASM 从本地服务加载。

市场价格仍使用两个外部接口：

- BDOlytics：通过同域代理获取所选服务器的市场价格。
- Arsha：在主接口请求失败（例如返回 403）或缺少部分物品价格时补价。

启动时读取与当前服务器一致的价格缓存；超过一小时或缓存属于其他服务器时，会请求更新。切换服务器或点击 **reload** 也会重新请求价格。连续切换时只采用最新请求的结果，旧请求不会覆盖新服务器的价格或加载状态。

获取最新市场价格需要网络连接。页面中的资料、物品详情和视频链接会在点击后打开外部网站。

## 测试与性能

```sh
npm test
npm run benchmark:performance
```

测试覆盖收益相关计算、距离索引、候选路径缓存失效、并行加载及状态保存等逻辑，也覆盖弹窗首次打开与城镇切换、价格导入和清空、市场请求乱序，以及优化参数变更后的旧方案拦截。

性能改动包括静态数据与 WASM 并行加载、路由和弹窗按需加载、路径与收益计算分离缓存，以及地图退出时取消请求并释放资源。测量环境和结果见 [性能报告](docs/performance.md)。

本轮进一步拆分界面语言和图表依赖，缓存优化器候选计算、复用 Worker，并减少主线程快照、签名和地图更新开销。具体结果与复测方法见 [2026-10-14 性能报告](docs/performance-2026-10-14.md)。基准会在相同真实游戏数据上对比保留的原算法，断言全部候选和基础设施结果一致；耗时仅用于同机对比。

`npm run lint` 可运行 ESLint，并自动修复可处理的问题。
