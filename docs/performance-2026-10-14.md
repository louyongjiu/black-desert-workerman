# 2026-10-14 性能优化与验证

本轮在现有工作区基础上继续优化，保留此前的住房、行情和交互改动。基准参考实现取自本轮修改前的代码，位于 `tests/fixtures/referenceCalculations.mjs` 和 `referenceValues.mjs`；不与 10 月 9 日的旧构建混用。

## 已实施的改动

- 技能候选排序和组合提前编译，同一工人模板的技能属性在一轮计算内复用。采集点的普通、巨人和幸运收益提前汇总，浮动资源按精确工作速度缓存周期，保持原有运算顺序和舍入。
- Worker 缓存城镇距离、连接成本及候选评分，连续求解复用 WASM 和静态数据。候选缓存最多 12,000 条，技能属性和资源周期缓存各自最多 512 条；完成后空闲两分钟释放 Worker，停止和异常立即释放。
- 主线程只发送动态参数与资源地址。Worker 直接加载版本化静态资源并核验签名，避免每次在主线程复制约 3 MB 的游戏数据。响应按任务编号过滤，已停止任务不会覆盖下一轮。
- 界面词典按五种语言、五个页面分组生成，只加载当前语言和需要的分组。导航、路由和异步弹窗等待对应词典就绪；快速切换语言采用最新选择，失败加载支持重试。
- 房屋树形图首次展开时才加载 ECharts。设置、资源和首页编辑弹窗延后加载，其研究词典随组件一起加载。
- 配置签名使用 Pinia 计算属性，一次状态变化只计算一次；城镇工人列表提前分组，工人行采用对象身份作为稳定键，并复用展示属性。
- 采集点排序与搜索分开计算，名称索引随语言更新。地图同一帧的图层请求合并，只重建需要变化的图层；切回已移除的地区图层时克隆实例，复用已下载数据。卸载取消待执行帧。
- 住房草稿持久化直接选择需要保存的字段，由持久化管理器统一序列化，省去中间的 JSON 复制；公开草稿投影接口默认仍返回独立副本。

## 测量条件与结果

Windows、Node.js 22.22，同一工作区真实游戏数据，所有相关行情价格固定为 1,000。每个候选场景分别执行三轮原算法、冷缓存和热缓存，取中位数；快照执行五轮。热缓存只修改求解时间上限，候选数据不变。结果通过完整 JSON 比较，包含候选顺序、收益、工人技能、缺价记录、住房与固定基础设施。

| 指标 | 本轮修改前 | 优化后 | 改善 |
|---|---:|---:|---:|
| 31 城镇、370 采集点，静态资源候选准备 | 14,205.95 ms | 冷缓存 3,201.28 ms | 77.5% |
| 同场景连续求解候选准备 | 14,205.95 ms | 热缓存 144.67 ms | 99.0% |
| 6 城镇、40 候选上限，浮动资源候选准备 | 7,023.83 ms | 冷缓存 1,210.45 ms | 82.8% |
| 同浮动资源场景连续求解候选准备 | 7,023.83 ms | 热缓存 48.20 ms | 99.3% |
| 主线程构造输入快照 | 150.09 ms | 6.40 ms | 95.7% |
| 输入快照 JSON 大小 | 3,002,792 B | 24,131 B | 99.2% |
| 生产入口脚本，未压缩 | 868,634 B | 304,601 B | 64.9% |
| 生产入口脚本，gzip | 226,253 B | 98,203 B | 56.6% |

这些测量只覆盖候选准备、快照构造和入口资源体积，不代表完整 HiGHS 求解速度或线上加载时间。首次启动 Worker 仍须读取并解析静态数据、加载 WASM；地图、图表和其他语言的资源在实际使用时加载。浮动场景的 40 是最终候选上限，候选准备仍会按原算法评估全部有效采集点后排名。

## 缓存正确性

静态游戏数据视为不可变；替换数据引用或版本会清空几何和技能缓存。候选评分键覆盖采集点、城镇、距离、完整工人模板、工作量、汇总收益、完整资源配置和物种限制。每轮技能属性缓存重置，工人模板原地修改也不会沿用旧属性。返回结果复制技能数组，调用者不能修改缓存内容。

预算、选中城镇、候选上限和每采集点候选数量继续按当前参数过滤与排序。住房保留、仓储容量及固定任务仍重新构造，未缓存求解结果，也未改变技能搜索范围或线性模型。价格或资源变化会使相关评分失效，冷缓存收益以原算法为准。

配置签名仅随结构字段变化重算。工人、技能、住房或游戏数据变化会使已应用方案失效；行情变化保留原路线，刷新收益。状态持久化、方案应用和撤销保持原有行为。

```sh
npm run build

```

基准执行时应避免同时构建或运行其他 CPU 密集任务。机器负载、浏览器、行情和资源设置均会影响耗时；有价格或工人模板变化时应预期部分缓存重新计算。界面词典修改请编辑 `src/i18n/` 源表，构建会重新生成 `data/ui/`。
