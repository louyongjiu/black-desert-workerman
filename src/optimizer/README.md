# 浏览器帝国优化器

联合选择采集点、工人城镇、连接节点和住房，使用 `highs@1.15.3` 的 HiGHS 1.15.1 WASM，在独立 Web Worker 中求解。

住房规划同时融合 [bdo-housecraft 0.3.18](https://github.com/Thell/bdo-housecraft/tree/3af0b47113c4709afab148ae2d3fa83748e08ac6) 的房屋依赖和用途互斥模型。存在手动保留或工作工坊占用的城镇按房屋建模，其他城镇继续使用原有预计算表；共享前置房屋只计一次成本。详细规则见 `src/housing/README.md`。

住房方式由共用的 `townHousingPolicy` 按城镇确定，并随结果写入 `housingMethod`，与住房页面和首页保持一致。只有实际派工的工坊触发占用；工坊配置列表和局部试算历史不作为房屋保留约束。普通城镇查表，受限城镇的房屋变量参与整个帝国联合求解；预计算表在受限城镇只用于构造初始方案。

模型和九技能候选搜索改写自 [Thell/bdo-empire v0.8.2](https://github.com/Thell/bdo-empire/tree/v0.8.2)，上游提交为 `955eddc50ecb89d06fe409a9c3136522ee4c637c`；其项目许可证声明为 [Unlicense](https://github.com/Thell/bdo-empire/blob/v0.8.2/pyproject.toml)。HiGHS JavaScript 包采用 MIT 许可证，随 npm 包保留其许可证。

发布目录包含完整的 HiGHS 与 highs-js 许可证，源文件位于 `public/licenses/highs.txt`，访问路径为 `/workerman/licenses/highs.txt`。

本实现使用当前 Workerman 游戏数据和有效价格，共享前端的静态/浮动资源周期计算；增加指定仓库的物品种类、额外槽位和住房联合成本约束。保留已有 Ancado 激活连接。上游经验性最低采集点数量约束未迁移，候选范围也由页面明确选择。

`model.mjs` 输出 CSR 稀疏矩阵；`result.mjs` 独立复核变量、所有线性约束、连接、住宿与仓储容量以及预算。清理结果时仅在求解器已选择的节点内取有效路径，避免引入预算外的连接。

新采集工人采用 40 级平均属性和九技能候选。`fixedWorkshops.mjs` 捕获工坊与闲置工人的记录、必需连接和仓储需求，保留真实等级、技能、配方与生产设置。工坊路径及 Ancado 必需激活路径固定，全部雇佣工人的床位与仓储进入同一住房模型；保留城镇不受新采集城镇选择限制。采集可复用工坊节点和仓库物品，节点与房屋按并集计费。

求解前先检查固定部分的最低可行贡献点；只有求解器证明最优才报告该底价，未证明时显示未知。固定需求超过预算或住房不可行时明确解释。缺价无候选不清空工人；仅保留固定工人的结果必须确认移除旧采集后才可应用。优化目标仍是新采集日收益，工坊和合计收益分开显示，缺失的工坊收益显示未知。

`application.mjs` 共用方案合并逻辑。应用与可导入导出保留当前工坊及闲置工人对象和相对顺序，生成原索引到最终索引的绑定；不依赖名字，也不从旧快照覆盖真实工人。应用在一次状态更新内写入，撤销替换恢复完整备份。`appliedRouting.mjs` 同时恢复工坊和采集路线，首页、地图及住房规划使用相同的结果。结构、房屋、仓储和游戏数据变更使方案失效；价格与工坊手填利润变化保留路线并更新首页收益。新版使用 schema 2，旧纯采集方案保持可读。

活动围栏、自定义、贸易或皇室工坊任务尚未建模，只提供明确标识的预览说明导出，不生成已应用的混合帝国。历史未启用的贸易配置保留。工坊生产、实际采集工人选配与原料供给量平衡不在本轮范围内。

WASM 和 Worker 仅在开始优化时加载。停止操作销毁 Worker，保留已经验证并传回页面的最佳可行解。新任务忽略旧 Worker 的迟到消息。

正常完成后保留 Worker，连续求解复用静态数据、WASM 和候选缓存；空闲两分钟后自动释放。停止、异常或重启正在运行的任务会销毁 Worker，下一次从冷启动开始。每条响应携带任务编号，旧任务的迟到消息不会覆盖当前结果。

主线程发送动态参数和带内容哈希的资源地址，Worker 自行加载静态数据，并核验游戏数据签名；版本不一致时要求刷新页面。`prepareValues` 的缓存最多保留 12,000 个城镇与采集点候选，价格、资源、工人模板和静态数据变化会使相应计算失效；预算和候选范围重新过滤。技能组合、浮动资源周期、候选顺序及住房模型保持原算法。细节与同机基准见 [性能报告](../../docs/performance-2026-10-14.md)。

求解前先构造包含连接流、住房和仓储容量的初始可行解，逐项校验后传给 HiGHS 继续改进。大范围模型可以较早显示该方案，无需等到完整搜索结束。

验证命令：

```sh
node --test tests/optimizer.test.mjs
npm test
npm run build
```

测试包含小图独立穷举、固定节点与混合任务并集成本、全部工人床位、材料/成品仓储去重和人工补充、192 格边界、重复名字与索引变化后的导出、旧纯采集住房兼容、实际游戏收益和贡献点复算、Ancado 连接、方案失效和 Worker 停止。浏览器检查覆盖混合应用/撤销/导出、工坊仓储补充、五种语言和手机布局。
