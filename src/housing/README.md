# 浏览器住房规划

房屋依赖、用途互斥和最小贡献点模型改写自 [Thell/bdo-housecraft 0.3.18](https://github.com/Thell/bdo-housecraft/tree/3af0b47113c4709afab148ae2d3fa83748e08ac6)，基线提交 `3af0b47113c4709afab148ae2d3fa83748e08ac6`，采用 Unlicense。原项目是原生 Rust/HiGHS 命令行工具，本实现使用已有的 HiGHS WASM 和 Web Worker，部署保持静态网站。许可证保留在 `public/licenses/housecraft.txt`。

游戏数据以当前 Workerman 的 `houseinfo.json` 为准；无约束方案继续使用已有的 `all_lodging_storage.json`。没有从上游数据包覆盖本地数据。当前快照包含 816 栋房屋、32 个有房屋的城镇，以及 8,717 条预计算方案；另外三个查表城镇只有不租房的零成本方案。

`core.mjs` 统一房屋容量、手动保留用途和正在工作的工坊占用，输出每栋房屋的租用、住宿、仓储及其他用途变量。后续房屋必须租用全部前置房屋，每栋房屋只能采用一个用途。前置房屋的用途仍可优化；住宅、马厩和工坊等锁定用途不贡献床位或仓库格数。住宿和仓储沿用数据支持的最高等级。

单城镇无约束时快速查表；有保留用途时由 `solve.worker.mjs` 按需求求解最小贡献点，默认时限 10 秒。只展示独立校验过的可行解；只有求解器证明最优才显示最低成本。停止会终止 Worker 并保留已验证方案，重新计算可以重试。`stores/housing.js` 合并相同请求，优先处理住房页面与首页需求，忽略旧 Worker 或旧约束的结果。

`townHousingPolicy` 是首页、单城镇试算和帝国优化共用的城镇分流规则：本城镇没有保留用途时查表；有手动用途或工作工坊占用时逐栋求解。其他城镇的限制、未派工的工坊配置和历史住房试算不会触发本城镇求解。结果保存 `housingMethod`，住房页面和帝国详情显示当前采用的方式；旧方案按原有标记兼容读取。全部查表城镇的对照见 [全城镇试算报告](../../docs/housing-all-towns-comparison.md)。

住房页面分为“帝国住房”和“自由试算”两个页签。帝国住房结果默认使用 `optimizerPlan` 或有效帝国预览的住房行，与首页和优化器共用一份配置；没有有效方案时显示当前工人与仓储需求的住房。`houseReservations` 是已保存的手动用途约束，正在工作的工坊自动保留，单纯添加到工坊配置列表不表示已占用。城镇总览分别显示手动用途、工坊房屋占用和工人居住城镇的仓储核对状态。

主导航进入帝国优化，再从计算前的两个住房入口进入对应页签。原 `/housecraft` 默认进入帝国模式，`?mode=trial` 直接进入自由试算；页面往返保留预算、范围、仓库和各城镇草稿。帝国模式的城镇选择提供“全部城鎮”，统一显示全部城镇的住房贡献点、床位与仓储汇总、逐城镇容量和房屋明细、跨城镇保留用途、工坊仓储及分城镇的依赖图；支持直接编辑对应城镇的工坊仓储。点击具体城镇返回编辑，未保存草稿保留。全城镇与单城镇结果共用同一份有效预览、已应用方案或当前配置，预览未包含的城镇不会混入旧工人需求。`?mode=empire&town=all` 可直接打开该总览。

`stores/housingWorkbench.js` 保存两套独立草稿，`drafts.mjs` 将输入持久化到本机。总览只叠加实际修改过的草稿，未修改的旧草稿不会遮住后续保存或导入的数据。帝国用途与工坊仓储编辑不立即写入 `user`，点击“保存设置并返回帝国优化”才一次保存所有已修改城镇。已保存方案在草稿编辑期间继续按旧设置显示，并提示保存后重新优化。“重设此城镇手动用途”只清除当前城镇草稿中的手动用途，保留工作工坊、仓储、付费容量和自由试算记录。草稿及已保存帝国设置分别可撤销；保存和撤销检查相关城镇的当前设置与工坊任务，避免覆盖其他位置的后续修改。

自由试算输入总工人数和总仓储需求，扣除本次的免费及付费容量后计算房屋需求；容量初始复制现有值，后续修改只作用于试算。“从帝国复制”是一次性的需求和用途快照，复制的工坊用途可在试算中修改，不改变真实工坊。只有点击“开始试算”才计算，输入变化保留并标记上一次结果。计算请求按模式隔离缓存与排队上下文，旧消息不会污染另一模式。直接打开自由试算不请求市场价格或初始化节点路由 WASM。

`housingPlans` 每城镇保存一份本机比较记录，新记录附带 `trialInputs` 和保存时间，继续使用原本的本地持久化与 JSON 导入导出。旧记录仍可比较、加载需求后重新计算。“重设目前试算”只清除本次输入与结果，保留已保存记录；删除记录提供独立撤销。试算编辑、计算、保存和删除均不改变帝国工人、住房用途、仓储或付费容量。草稿输入在刷新后恢复；试算的运行句柄及未保存计算结果不跨刷新恢复，需要重新计算。已保存的试算记录继续可用。

首页使用同一模型计算基础设施。所有已雇佣工人，包括闲置工人，都计入床位需求。基础床位、基础仓库、付费容量、价值礼包和个人仓储设置按现有规则扣除。工坊自身贡献点按房屋数据计入工坊成本，其余租用房屋计入住房成本，二者合计等于房屋并集成本。旧 `manualCp` 字段仍保留，但不重复计入贡献点。

`requirements.mjs` 统一首页与帝国的仓储统计。工坊材料/成品存入工人居住城镇，同一仓库的已知可堆叠物品按编号去重，和采集物品共用；保留一个备用格。不可堆叠或堆叠属性未知的物品需要填写预留件数/格数。缺失配方可补充物品编号和额外格数，核对后确认。`workshopStorage[城镇]` 保存 `coverage`、`manualItems`、`itemSlots`、`extraSlots`、`personalIncludes` 和 `confirmed`。存在旧个人预留时，用户明确选择全部由个人预留覆盖，或指定从原预留迁出的工坊份额；不自动猜测重叠。修改输入会重置确认。

实际仓储需求受每城镇 192 格限制，基础与付费容量已包含在上限内。依据 [黑色沙漠繁体中文官方仓库指南](https://www.tw.playblackdesert.com/zh-tw/Wiki?wikiNo=25)；工坊所在城镇与工人居住城镇的连接、材料/成品存放规则见 [官方据点与制作指南](https://www.naeu.playblackdesert.com/en-us/Wiki?wikiNo=20)。超限或数据未确认时显示问题，不生成可应用的帝国方案。

新确认附带 `confirmedFor`，绑定当前配方及个人/工坊预留内容。配方或相关需求变化后需要重新核对；旧显式确认格式保持兼容。导入按文件提供的字段完整替换状态，包括空映射，并清除旧优化预览，避免旧房屋、付费容量或工人绑定残留。

帝国优化器对存在保留用途的城镇直接加入上述房屋变量，没有用途限制的城镇仍使用预计算方案。旧方案经保留用途修复后只能作为初始可行解，不能当作完整的最优候选集合。锁定房屋所在城镇即便未勾选为工人城镇，也计入房屋预算。结果复核用途、依赖、容量和预算，应用后首页保留该方案的房屋配置；改变用途或房屋数据会使保存的优化路径失效。

新采集工人继续采用 40 级平均属性。现有工坊的真实工人、配方与生产设置保留，其路线、床位和仓储进入同一个帝国预算。工坊生产选址和配方不参与优化。自动工坊占用继续由保留的任务推导，不转成永久手动锁定。应用后结构和仓储变化使原方案失效；市场价格或手填工坊利润变化只更新收益，已应用路线继续有效。

验证覆盖小模型独立穷举、全部预计算方案的容量/成本/依赖检查、所有查表城镇的代表性最低成本、卡尔佩恩/瓦伦西亚/海地尔约束求解、工作工坊与共享前置成本、Worker 重试及迟到消息、真实帝国预算与应用后的首页成本。
