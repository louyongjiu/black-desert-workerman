# 浏览器住房规划

房屋依赖、用途互斥和最小贡献点模型改写自 [Thell/bdo-housecraft 0.3.18](https://github.com/Thell/bdo-housecraft/tree/3af0b47113c4709afab148ae2d3fa83748e08ac6)，基线提交 `3af0b47113c4709afab148ae2d3fa83748e08ac6`，采用 Unlicense。原项目是原生 Rust/HiGHS 命令行工具，本实现使用已有的 HiGHS WASM 和 Web Worker，部署保持静态网站。许可证保留在 `public/licenses/housecraft.txt`。

游戏数据以当前 Workerman 的 `houseinfo.json` 为准；无约束方案继续使用已有的 `all_lodging_storage.json`。没有从上游数据包覆盖本地数据。当前快照包含 816 栋房屋、32 个有房屋的城镇，以及 8,717 条预计算方案；另外三个查表城镇只有不租房的零成本方案。

`core.mjs` 统一房屋容量、手动保留用途和正在工作的工坊占用，输出每栋房屋的租用、住宿、仓储及其他用途变量。后续房屋必须租用全部前置房屋，每栋房屋只能采用一个用途。前置房屋的用途仍可优化；住宅、马厩和工坊等锁定用途不贡献床位或仓库格数。住宿和仓储沿用数据支持的最高等级。

单城镇无约束时快速查表；有保留用途时由 `solve.worker.mjs` 按需求求解最小贡献点，默认时限 10 秒。只展示独立校验过的可行解；只有求解器证明最优才显示最低成本。停止会终止 Worker 并保留已验证方案，重新计算可以重试。`stores/housing.js` 合并相同请求，优先处理住房页面与首页需求，忽略旧 Worker 或旧约束的结果。

用户状态新增 `houseReservations`、`housingPlans` 和 `housingUndo`。正在工作的工坊自动保留，单纯添加到工坊配置列表不表示已占用。手动锁定或保存方案支持一步撤销；状态随原有本地存储和 JSON 导入导出保存。保存只记录网页里的计划，不操作游戏。方案缓存键包含本城镇房屋数据、用途限制与需求，数据或需求变化后不再直接采用旧方案。

首页使用同一模型计算基础设施。基础床位、基础仓库、付费容量、价值礼包和个人仓储设置仍按现有规则扣除。工坊自身贡献点按房屋数据计入工坊成本，其余租用房屋计入住房成本，二者合计等于房屋并集成本。旧 `manualCp` 字段仍保留在用户数据中，但不再用来重复计入房屋贡献点。工坊材料占用的仓储格数仍需通过个人仓储设置提供。

帝国优化器对存在保留用途的城镇直接加入上述房屋变量，没有用途限制的城镇仍使用预计算方案。旧方案经保留用途修复后只能作为初始可行解，不能当作完整的最优候选集合。锁定房屋所在城镇即便未勾选为工人城镇，也计入房屋预算。结果复核用途、依赖、容量和预算，应用后首页保留该方案的房屋配置；改变用途或房屋数据会使保存的优化路径失效。

采集工人继续采用 40 级平均属性。当前版本把工坊作为固定房屋用途，不优化工坊选址、配方利润或已有工人属性。含工坊等其他任务的帝国仍沿用既有直接应用限制；导出的采集方案把自动工坊占用转为手动房屋保留，避免丢失房屋约束。

验证覆盖小模型独立穷举、全部预计算方案的容量/成本/依赖检查、所有查表城镇的代表性最低成本、卡尔佩恩/瓦伦西亚/海地尔约束求解、工作工坊与共享前置成本、Worker 重试及迟到消息、真实帝国预算与应用后的首页成本。
